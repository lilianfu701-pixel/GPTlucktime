# DateCN 免费 Vercel 测试部署设计

日期：2026-08-24  
状态：用户已确认方案，等待书面档案复核

## 目标

把当前已完成的 DateCN 网站发布为可通过公网访问的测试站，并在验收通过后把 `datecn.org` 指向该测试站。测试阶段不购买服务器、不升级 Vercel 套餐、不绑定自动付费服务，也不接收真实用户资料。

本次必须能看到和试用：首页、注册登录、会员中心、搜索匹配、个人资料、消息及移动端界面。支付、邮件、短信和实名认证保留完整界面与测试流程，但不执行真实扣款或向真实联系人发送信息。

## 已确认约束

- 所有组件只使用免费方案或免费额度。
- 不填写银行卡，不开启付费套餐，不接受可能自动续费的试用。
- 只使用合成测试账号、测试图片和测试消息。
- 域名切换必须可回滚；在测试地址验收通过前不修改现有 DNS。
- 该环境仅用于开发测试，不作为正式商业运营环境。
- 任何免费额度不足、供应商要求付款方式或功能无法免费实现时，停止该项操作并记录，不擅自降级安全要求。

## 方案比较

### 方案 A：Vercel 免费测试栈（采用）

Vercel Hobby 承载 Next.js 网站与接口；Neon Free 承载 PostgreSQL；Upstash Free 承载 Redis；Vercel Blob 免费额度承载测试图片。消息通过短间隔自动刷新完成，不部署常驻 WebSocket 服务器。

优点是没有固定费用、没有服务器运维，并且最符合“先用 Vercel 看到完整效果”的目标。代价是免费额度可能暂停，消息存在数秒延迟，不能作为正式运营架构。

### 方案 B：Vercel Services 测试版

把网站与现有 Socket.IO 服务一起放入 Vercel Services。它能保留即时消息连接，但该能力仍是测试功能并可能需要单独开通，免费账号上的可用性不可保证，因此不用于本轮发布。

### 方案 C：Vercel 加独立服务器

网站放 Vercel，实时消息和存储放独立服务器。稳定性更高，但会引入服务器费用和运维，与本轮零付费约束冲突，因此排除。

## 系统结构

1. **网站与接口**：现有 Next.js 应用部署到一个独立的 Vercel 项目，使用独立项目名和独立环境变量，不与以往项目共享运行配置。
2. **数据库**：新建独立 Neon Free 数据库，执行现有 41 组数据库迁移，然后只写入合成测试数据。
3. **缓存与限流**：新建独立 Upstash Free Redis，供登录保护、限流和后台队列协调使用。
4. **测试图片**：使用独立 Vercel Blob 存储。现有 S3 存储边界将增加 Blob 适配，不把访问令牌暴露给浏览器。
5. **消息**：保留现有消息数据库、授权、恢复、已读回执和屏蔽规则；测试部署使用网页定时拉取新消息，间隔约两秒。浏览器关闭后不维持常驻连接。
6. **外部服务**：Stripe、邮件、短信、身份验证和内容审核只启用安全的测试适配器或明确的“测试中”状态；不使用真实密钥和真实联系人。
7. **域名**：先使用 Vercel 提供的临时地址验收。通过后，在 Vercel 添加 `datecn.org` 和 `www.datecn.org`，再按 Vercel 实际给出的记录修改 Cloudflare DNS。

## 数据流与安全边界

- 浏览器只获得公开网址和一次性上传凭证，不获得数据库、Redis、Blob 或签名密钥。
- 注册、资料、匹配和消息请求先经过服务器端会话与授权校验，再访问数据库。
- 图片先进行大小、数量和类型检查，再写入测试存储；测试阶段不上传真实证件或敏感照片。
- Redis 不作为事实数据源，清空缓存不得导致账号、消息或资料丢失。
- 所有生产形态的密钥均随机生成并只存于 Vercel 环境变量；代码库和部署档案中不记录密钥值。
- 测试模式必须在界面上清楚标识，避免用户误以为支付、认证或通知已正式开通。

## 免费额度与失效处理

当前 Vercel Hobby 的 Fluid Active CPU 已超过免费额度，控制台显示本次 30 天窗口为 2026-07-25 22:00 至 2026-08-24。首次部署等待该窗口更新后进行，不新建账号规避额度限制。

若任何免费服务出现以下情况，部署停止在可回滚状态并记录原因：

- 要求填写付款方式或同意自动续费；
- 免费配额不足以完成迁移或验收；
- 无法选择独立区域或无法满足加密连接；
- 服务端凭据会暴露到客户端；
- 测试站因供应商配额被暂停。

## 部署顺序

1. 准备独立、可持续更新的代码来源和 Vercel 项目配置。
2. 完成消息轮询与 Blob 存储兼容改造，并通过本地测试。
3. 创建免费的数据库、Redis 和 Blob 测试资源，写入部署环境变量。
4. 执行数据库迁移和合成测试数据初始化。
5. 部署到 Vercel 临时地址并完成桌面端、移动端和主要流程验收。
6. 保存 Cloudflare 当前 DNS 值，添加 Vercel 域名并获取项目专属 DNS 要求。
7. 在最终确认后切换 `datecn.org`，验证 HTTPS、跳转、登录、匹配、资料和消息。
8. 记录部署地址、资源名称、额度和回滚步骤，不记录任何密钥。

## 验收标准

- Vercel 临时地址和 `https://datecn.org` 均能正常打开，HTTPS 有效。
- 中英文首页、注册登录、会员中心、搜索匹配、个人资料和消息页面可用。
- 手机宽度下没有横向溢出，主要按钮与表单可操作。
- 两个合成测试账号可完成匹配并互发消息；新消息最迟在数秒内出现。
- 上传的测试图片可显示、替换和删除，且不能读取他人的私有对象。
- 未配置的真实支付、通知和认证不会伪装成功，也不会产生外部操作。
- 所有自动测试、类型检查、构建检查和部署后的浏览器冒烟测试通过。
- DNS 回滚记录完整；恢复旧记录后能回到切换前状态。

## 域名回滚

切换前记录 `datecn.org` 和 `www.datecn.org` 的原始记录、代理状态和 TTL。若 Vercel 域名验证、证书、登录回调或关键页面出现故障，立即恢复原记录。只有临时地址验收通过后才允许修改 DNS，且使用 Vercel 项目检查页面显示的实际记录，不依赖通用示例值。

## 明确不在本轮范围

- 真实收费会员、真实 Stripe 结算和退款。
- 真实邮件、短信、实名认证和人工审核供应商。
- 正式运营 SLA、无限流量或免费额度之外的自动扩容。
- 真实用户导入和真实身份资料上传。
- 付费监控、付费备份和付费域名迁移。
