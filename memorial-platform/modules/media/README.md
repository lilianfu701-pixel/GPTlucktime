# 媒体管线

## 1. 已完成

- **类型白名单**（`policy.ts`）：按文件自身前导字节匹配，不信任客户端声明的 MIME。
- **对象键构造**：完全由服务端生成的标识符拼成，客户端文件名永不进入路径。
- **生命周期**：`pending_upload → scanning → processing → ready`，失败进 `rejected`。
  未检查的字节只存在于 `quarantine/` 前缀，任何东西都不从那里对外提供。
- **地址策略**：只有「public 主页 + ready 资产」才可能有永久公开地址，其余一律短期签名 URL。
- **存储接口** `MediaStorage` + 内存适配器，管线可在无网络的情况下完整测试。

- `AlwaysCleanScanner` —— 一个「所有文件都干净」的扫描器比没有扫描器更糟，
  因为它让管线**看起来**是完整的。

## 3. 为什么用白名单而不是黑名单

拒绝清单永远落后于下一个 polyglot 文件，或下一个被发现解码器漏洞的格式。
白名单的代价是新格式要显式加入，收益是未知格式默认被拒。

**SVG 被刻意排除。** 它是可携带脚本的文档，接受它等于在家属发给亲友的页面上
放一个 XSS 入口。

## 4. 声明类型要检查两次

签名时检查是为了在发 URL 之前就挡掉明显不合规的上传。
**字节到达后必须再检查一次** —— 签名 URL 规定的是「允许上传什么」，
不保证「实际上传了什么」。

声明为 JPEG 的可执行文件不是需要纠正的标注错误，那就是攻击本身，所以直接拒绝。
