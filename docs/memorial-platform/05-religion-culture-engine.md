# 05. 宗教与文化习俗引擎

## 1. 目标

宗教与文化引擎负责提供经过来源和人工审核的纪念方式建议，但最终决定权属于家属。系统不能因为选择某种宗教就自动启用全部相关仪式，也不能将一个地区或宗派的做法描述为所有信徒的统一规则。

## 2. 分类层级

分开建模：

- 宗教；
- 宗派或传统；
- 国家或地区；
- 族群文化；
- 家庭习俗；
- 逝者个人意愿；
- 是否公开信仰。

基础宗教分类：

- 无宗教或世俗纪念；
- 基督宗教；
- 伊斯兰教；
- 佛教；
- 道教和中国民间传统；
- 印度教；
- 犹太教；
- 锡克教；
- 神道教；
- 巴哈伊信仰；
- 原住民或地方传统；
- 多重传统；
- 家属自定义；
- 不公开信仰。

分类记录只是目录，不等同于教义声明。

## 3. 仪式定义

每种祭奠方式拥有稳定 definition 和不可变 version。

版本必须包含：

- 内部稳定标识；
- 本地化名称和说明；
- 动作类型；
- 适用宗教、宗派、地区和文化；
- 推荐或限制条件；
- 可否匿名；
- 可否留言；
- 是否建议预审；
- 周年和历法规则；
- 禁忌及冲突标签；
- 资料来源；
- 审核人和审核日期；
- 生效和停用状态。

首批动作：

- 献花；
- 点纪念蜡烛；
- 上香；
- 祈祷或代祷；
- 诵经或经文纪念；
- 献石；
- 默哀；
- 鞠躬；
- 留下思念；
- 分享回忆；
- 公益捐赠；
- 植树纪念；
- 虚拟供品；
- 周年纪念；
- 家庭自定义动作。

## 4. 兼容规则

| 等级 | 系统行为 |
|---|---|
| `recommended` | 可以向家属推荐，但不自动启用 |
| `optional` | 可出现在“其他可能合适” |
| `needs_family_confirmation` | 明确解释差异并要求家属确认 |
| `not_recommended` | 默认不展示，可由后台说明原因 |
| `prohibited_combination` | 阻止该组合并显示中性解释 |

多个规则冲突时采用最严格结果。无法确定适用性时返回“不推荐任何动作”，而不是猜测。

## 5. 家属控制

每个主页逐项保存：

- 是否启用；
- 采用的仪式版本；
- 家庭自定义显示名称；
- 是否允许匿名；
- 是否允许留言；
- 留言先审或后审；
- 家属确认时间和操作者。

目录版本更新不会自动更改现有主页。如果旧版本因严重错误被停用，系统通知所有者重新确认替代版本，并允许平台在安全事件中暂停该动作。

## 6. 审核工作流

状态：

```text
draft → in_review → published → retired
```

发布要求：

- 至少一项可核验资料来源；
- 明确适用宗教、宗派、文化或地区；
- 明确不适用范围；
- 宗教或文化审核人批准；
- 对启用语言存在人工审核翻译；
- 记录审核日期；
- 不包含平台自行断言的灵魂归宿或教义结论。

编辑已发布规则必须创建新版本。后台不允许覆盖历史版本。

## 7. 翻译规则

- 宗教术语必须维护术语表；
- 机器翻译只能进入草稿；
- 原始资料引用不由机器改写含义；
- 不同宗派采用不同术语时分别保存；
- 争议词汇用中性说明，不强行统一；
- 页面必须标注内容来源和适用范围。

## 8. 历法

适配器接口必须保存：

- 历法 ID；
- 实现版本；
- 原始日期；
- 转换后的公历日期；
- 纪念地时区；
- 下一次周年日期；
- 转换错误状态。

第一阶段完整实现公历适配器，其他历法先实现接口和明确的 `CALENDAR_NOT_CONFIGURED` 响应。系统不得使用每隔 365 天作为通用周年算法。

## 9. 安全默认

- 未选择宗教时只提供世俗中性动作候选；
- 选择宗教后仍需家属逐项启用；
- 资料不足时不推荐；
- 用户自定义动作默认仅用于当前主页；
- 自定义动作若进入公共目录，必须完成完整审核；
- 不出售宗教动作的高级排名或突出显示；
- 公益捐赠与普通祭奠数据分离，未来需要单独的资金合规设计。
