# 全球多语言网上追思平台设计规格

日期：2026-07-28  
状态：已完成产品讨论，待用户审阅书面规格  
技术路线：TypeScript + Next.js 模块化单体

## 1. 能力定义

平台面向全球用户，为逝者的配偶或近亲属提供创建、维护和治理正式追思主页的能力。公众可以搜索公开主页，并按照家属选择的宗教、文化或世俗方式进行线上祭奠。平台必须尊重不同信仰、宗派、地区和家庭习俗，不预设任何宗教为默认，也不把不同文化的仪式混合成固定模板。

首版采用轻审核。创建者使用已验证账号登录，声明其与逝者的关系并接受真实性及管理责任承诺。发生重复主页、身份冒用或归属争议时进入举报与申诉流程，平台可在争议处理中要求补充关系或死亡证明。

## 2. 固定产品规则

- 只有逝者的配偶、父母、子女或兄弟姐妹可以申请创建正式追思主页。
- 朋友和公众不能创建正式主页，但可在权限允许时访问、祭奠、留言和投稿。
- 创建者默认成为主页所有者，并可邀请其他家属共同管理。
- 同一逝者原则上只有一个正式主页；高相似记录触发重复检测和加入、申诉或合并流程。
- 新主页默认公开，进入站内搜索，并默认允许搜索引擎收录。
- 家属可以随时切换为“仅链接可见”或“仅受邀访问”。
- 基础追思主页永久免费，不因未付费而删除。
- 基础祭奠动作永久免费，不设置付费排名或“更有诚意”的高价祭品。
- 第一阶段不开放支付，但数据模型预留套餐、权益、订阅和订单。
- 手机号注册登录完整开发并测试，但第一阶段通过功能开关隐藏。

## 3. 明确非目标

第一版不包含：

- 原生 iOS 或 Android 应用；
- 微服务拆分和全球多区域数据库写入；
- 政府死亡登记、医疗证明签发或实体遗体管理；
- 默认强制上传死亡证明；
- 自研视频直播系统；
- 正式支付、自动续费或退款流程；
- 公开祭奠排行榜、虚拟祭品竞价、NFT 或数字遗产交易；
- 自动生成宗教教义结论；
- 未经人工审核直接发布由机器生成的宗教规则；
- 将任一宗教、文化或仪式设为全球默认。

## 4. 技术架构

### 4.1 技术选型

- 主要语言：TypeScript
- Web 框架：Next.js
- 数据库：PostgreSQL
- ORM：Drizzle ORM
- 缓存、限流和任务队列：Redis
- 文件与媒体：S3 兼容对象存储
- 搜索：首版使用 PostgreSQL 全文搜索和相似度查询
- 媒体与后台任务：独立 Worker 进程
- 部署：CDN/WAF 前置，应用和数据库按环境隔离

### 4.2 架构策略

首版使用模块化单体。所有模块部署为一个应用，但领域边界、服务接口和数据访问规则保持独立。搜索、通知、媒体处理和内容审核在规模增长后可拆成独立服务。

领域模块：

1. 身份与家庭关系
2. 逝者与追思主页
3. 生平、时间线与媒体
4. 线上祭奠
5. 留言与内容投稿
6. 搜索与发现
7. 多语言与地区化
8. 宗教与文化仪式配置
9. 隐私、邀请与权限
10. 举报、申诉与审核
11. 通知与纪念日
12. 套餐与权益
13. 管理后台

### 4.3 运行拓扑

```text
全球访客
   |
CDN / WAF / DDoS 防护
   |
Next.js Web 应用
   |-- PostgreSQL：核心事务数据与首版搜索
   |-- Redis：缓存、限流、任务队列
   |-- S3：公开媒体、私密媒体、申诉材料
   |-- Worker：媒体处理、通知、索引和清理
   `-- 邮件/短信供应商抽象层
```

开发、测试、预发布和生产环境必须隔离。宗教仪式、翻译、套餐权益和功能开关通过后台配置发布，不要求重新部署应用。

## 5. 用户、身份与权限

### 5.1 登录能力

首发前台显示邮箱登录以及选定的 Google、Apple 第三方登录。手机登录后端同时开发，包含：

- E.164 国际号码标准化；
- 国家或地区代码选择；
- 短信验证码挑战、过期时间和尝试次数；
- 发送频率限制和异常检测；
- 手机绑定、解绑及账号合并；
- 短信供应商抽象接口；
- `phone_auth_enabled` 全球开关；
- `phone_auth_regions` 地区开放名单。

手机号不是唯一永久身份凭证。高风险变更需要已有登录会话或第二身份因子确认。

### 5.2 主页角色

- 所有者：修改隐私、宗教习俗、成员、管理权和删除申请。
- 管理员：管理内容、媒体、留言、祭奠和邀请。
- 编辑者：编辑生平、时间线和媒体。
- 审核者：审核访客留言、照片和故事。
- 受邀访客：访问受邀主页并按配置祭奠。
- 公开访客：访问公开主页或通过链接访问“仅链接”主页。
- 平台审核员：处理举报、申诉和违规内容，不能替家属随意重写生平。
- 超级管理员：系统配置和重大争议处理，所有操作强制写入审计日志。

所有权限均由服务端执行，前端隐藏控件不构成权限保护。

## 6. 追思主页

### 6.1 创建信息

- 姓名、曾用名、原文姓名、音译名和不同语言姓名；
- 头像、封面、生卒日期和地点；
- 可选性别字段；
- 生平简介和完整传记；
- 家庭关系和重要人物；
- 宗教、宗派、文化传统或无宗教；
- 允许的线上祭奠形式；
- 隐私等级、搜索引擎收录和互动权限；
- 创建者关系声明和真实性承诺。

姓名不强制翻译。日期允许不完整或不确定，并保存精度和说明，避免虚构具体日期。

### 6.2 内容

- 生平首页
- 人生时间线
- 照片、视频和音频
- 纪念文章和家书
- 家庭关系展示
- 葬礼、追思会和周年活动
- 家属公告
- 访客故事、照片和纪念投稿
- 分享链接和二维码
- 数据导出和纪念册生成接口

第一版不展示热门逝者、祭奠数量排行榜或访客竞争指标。

## 7. 宗教与文化习俗引擎

### 7.1 建模原则

系统采用“宗教中立核心 + 可审核仪式配置”。宗教、宗派、国家或地区、族群文化和家庭习俗分别存储，不能假设一种宗教只有一种统一做法。

基础分类包括：

- 无宗教或世俗纪念
- 基督宗教：天主教、东正教、新教及具体宗派
- 伊斯兰教：逊尼派、什叶派及其他传统
- 佛教：汉传、藏传、南传及日本佛教宗派
- 道教与中国民间传统
- 印度教
- 犹太教
- 锡克教
- 神道教
- 巴哈伊信仰
- 原住民或地方传统
- 多重传统
- 家属自定义
- 不公开信仰

### 7.2 仪式记录

每项仪式至少包含：

- 稳定标识、显示名称和动作类型；
- 适用宗教、宗派、地区和文化；
- 图标、颜色和说明文字；
- 是否允许留言和匿名；
- 是否需要家属或平台审核；
- 适用日期、周年和宗教历法规则；
- 禁忌、冲突及风险标签；
- 各语言翻译；
- 资料来源、顾问审核状态和最近审核日期；
- 发布版本、生效时间和停用状态。

首批动作类型包括献花、纪念蜡烛、上香、祈祷或代祷、诵经或经文纪念、献石、默哀、鞠躬、留言追思、分享回忆、公益捐赠、植树纪念、虚拟供品、周年纪念和家属自定义动作。

### 7.3 三层控制

1. 平台依据宗教、宗派、文化、地区和语言生成候选建议。
2. 家属逐项开启、关闭或调整显示名称。
3. 访客只能使用家属已批准的动作。

选择宗教不会自动启用全部相关仪式。规则服务不可用或置信度不足时，不推荐仪式，由家属手动选择。

### 7.4 兼容与禁忌

兼容等级：

- `recommended`
- `optional`
- `needs_family_confirmation`
- `not_recommended`
- `prohibited_combination`

涉及灵魂归宿、轮回、骨灰、实体供品或教义判断的文案不得作为通用默认内容。所有宗教规则必须记录来源、适用范围、争议说明和版本历史。机器翻译只能作为草稿，宗教术语需由相应语言的人工审核者校对后发布。

### 7.5 历法

系统预留公历、伊斯兰历、希伯来历、中国农历、佛教纪年或地区规则以及家庭自定义日期。数据库保存原始历法、原始日期、换算后的公历日期、时区和换算规则版本。周年提醒不能简单按 365 天计算。

## 8. 祭奠与互动

祭奠流程：

1. 验证主页访问权限。
2. 读取家属启用的祭奠动作。
3. 访客选择动作并可附短留言。
4. 执行限流、垃圾内容和安全检查。
5. 根据主页设置立即显示或等待审核。
6. 以幂等键保存祭奠记录。
7. 更新非竞争性统计并按设置通知家属。

家属可分别控制匿名祭奠、留言、照片投稿、先审后发和每种祭奠动作。通知失败不回滚已经成功的祭奠。

## 9. 隐私、搜索与发现

### 9.1 隐私等级

1. 公开：进入站内搜索，可由家属控制是否允许搜索引擎收录。
2. 仅链接：不进入站内搜索，不允许搜索引擎收录，持链接者可访问。
3. 仅受邀：登录并获得邀请后才能访问和祭奠。

公开转为仅链接时，系统立即从站内索引移除并输出 `noindex`。公开转为仅受邀时，原公开链接不再直接开放。私密转公开时，所有者必须二次确认个人资料和搜索引擎收录。

### 9.2 搜索能力

- 姓名、别名、原文姓名和音译；
- 出生或逝世年份；
- 国家、地区和城市；
- 公开生平内容和关键词；
- 模糊拼写和相似度匹配；
- 不同文字系统下的搜索别名。

仅公开主页进入搜索索引。搜索接口实施分页、限流和防批量抓取策略。首版首页不提供“热门逝者排行榜”，只允许展示获得家属授权的公共纪念专题。

### 9.3 重复主页

系统根据姓名、别名、生卒日期、地点和关系信息生成候选相似度。高相似候选在发布前提示申请人加入现有主页或发起归属申诉；不能仅凭算法自动合并或删除主页。

## 10. 多语言与地区化

界面语言和用户内容语言分离。每篇内容保存原始语言，人工翻译和机器翻译作为独立版本，机器翻译必须标注且不得覆盖原文。

首发批次：

1. 英语、简体中文、西班牙语
2. 巴西葡萄牙语、法国法语、德语
3. 阿拉伯语、繁体中文、日语
4. 俄语、印尼语、越南语、韩语

首阶段即实现全部 locale 的扩展机制，并把阿拉伯语 RTL 纳入自动化和人工验证。繁体中文至少区分 `zh-TW` 和 `zh-HK`，葡萄牙语数据结构区分 `pt-BR` 和 `pt-PT`。

地区化必须覆盖姓名顺序、日期、数字、时区、复数规则、文本方向和本地化搜索。所有时间以 UTC 保存，并携带用于展示和纪念日计算的时区。

```text

追思主体
```

## 12. 举报、申诉与治理

- 任何人可以举报身份冒用、错误资料、仇恨内容或隐私侵害。
- 更近亲属可以提交管理权申诉。
- 争议期间可限制编辑、限制互动或暂时隐藏主页。
- 审核员可以合并重复主页，但必须保留原内容、贡献者和迁移记录。
- 申诉证明材料使用独立私密存储，并执行更严格的访问审计。
- 处理结果通知相关双方，并提供一次复核入口。
- 未成年人和高风险个案在创建时提供非公开模式提示。
- 图片上传时移除 EXIF 位置信息，媒体在公开前完成恶意文件扫描。

### 13.1 永久免费

- 一个完整追思主页
- 基础生平和时间线
- 有限的照片和视频空间
- 全部基础祭奠动作
- 搜索、分享和隐私控制
- 留言审核
- 两名家庭管理员

### 13.2 高级权益预留

- 更大媒体空间和高清视频
- 更多管理员和细分权限
- 高级主题和自定义域名
- 高清纪念册或 PDF
- 自动纪念日提醒
- 私人线上追思活动
- 访客数据分析
- 批量媒体上传
- 长期数字保管方案

第一阶段只实现套餐、功能、权益、订阅、订单和主页权益的数据结构及功能开关，不展示购买入口，不创建真实支付或续费。

## 14. 核心业务流程

### 14.1 创建主页

1. 用户登录并验证邮箱或第三方身份。
2. 声明与逝者的关系并接受责任承诺。
3. 输入逝者基本信息。
4. 系统执行重复主页匹配。
5. 用户选择宗教、宗派、文化传统或无宗教。
6. 系统生成仪式候选建议。
7. 家属逐项确认祭奠方式。
8. 选择隐私、搜索引擎和互动权限。
9. 发布主页并记录审计事件。
10. 异步建立搜索索引和媒体变体。

### 14.2 隐私切换

- 公开转私密：事务内修改访问状态并提交索引删除任务。
- 索引服务失败：主页仍按新权限拒绝访问，删除任务进入重试队列。
- 删除主页：先进入可恢复期，再执行媒体、搜索索引和派生数据清理。
- 所有隐私变更记录操作者、时间、旧值、新值和原因。

### 14.3 内容投稿

访客投稿进入主页配置的审核路径。审核者可以批准、拒绝或要求编辑，但不能改变投稿者身份。被拒绝内容不进入公开搜索。所有审核动作写入审计记录。

## 15. 故障与恢复

- 媒体使用签名上传 URL，上传后执行扫描和异步转码。
- 搜索索引失败进入指数退避重试，不阻止主页事务完成。
- 通知失败不回滚祭奠、邀请或内容操作。
- 翻译失败时始终展示原始内容。
- 宗教规则查询失败时不自动推荐仪式。
- 后台任务具有幂等键、重试上限和死信记录。
- 关键管理操作需要二次确认。
- 数据库每日备份，并定期执行可验证的恢复演练。

## 16. 安全、隐私和可访问性

- 所有传输使用 TLS。
- 敏感字段和私密申诉材料静态加密。
- 私密页面和媒体禁止公共 CDN 缓存。
- 公开媒体使用不可预测对象键，不以对象键代替访问控制。
- 登录、祭奠、搜索、邀请和举报接口实施分级限流。
- 关键服务提供结构化日志、指标、健康检查和告警。
- 达到 WCAG 2.2 AA 目标。
- 创建、访问、祭奠和审核流程可使用键盘和屏幕阅读器。
- 多语言页面设置正确的 `lang`、`dir`、canonical 和 hreflang。

## 17. 测试策略

必须覆盖：

- 角色与资源的权限矩阵；
- 公开、仅链接、仅受邀三种隐私模式；
- 隐私变更后的访问拒绝和搜索索引删除；
- 多语言、RTL、姓名格式、音译和时区；
- 宗教仪式兼容、禁忌、来源和版本规则；
- 主页重复匹配、加入和申诉；
- 手机登录功能完整但 UI 隐藏；
- 祭奠幂等、垃圾请求和匿名限制；
- 媒体扫描、EXIF 移除和私密访问；
- 管理权申诉和审计日志完整性；
- 数据导出、软删除、恢复期和最终清理；
- 数据库备份恢复。

测试层次包括领域单元测试、数据库集成测试、API 契约测试、关键路径端到端测试和预发布环境安全验证。

## 18. 分阶段交付

### 阶段一：平台基础

项目骨架、模块边界、数据库、Redis、对象存储、邮箱和第三方登录、隐藏的手机登录、权限、审计、功能开关、多语言基础和 RTL。

### 阶段二：追思主页

关系声明、创建和编辑、生平、时间线、媒体、三种隐私模式、家庭共同管理、数据导出和删除流程。

### 阶段三：宗教与祭奠

宗教与文化模型、仪式库、翻译、兼容规则、版本控制、家属选择、访客祭奠、留言审核、宗教历法扩展接口和后台词条审核。

### 阶段四：搜索与治理

姓名、别名、音译、地区和内容搜索，重复检测、举报、封禁、管理权申诉、搜索引擎收录与移除、人工审核队列。

### 阶段五：商业化预留与上线

权益模型、功能统计、性能、安全、无障碍、恢复演练、分批语言验收和受邀家庭试用。

## 19. MVP 验收标准

- 合格家属可创建、编辑和共同管理一个追思主页。
- 新主页默认公开且可以被站内搜索。
- 家属可切换仅链接或仅受邀访问。
- 主页支持生平、时间线、照片和纪念文章。
- 家属可选择宗教、文化传统及允许的祭奠方式。
- 访客只能执行家属已经批准的祭奠。
- 每项发布仪式具有来源、适用范围、翻译、版本和审核状态。
- 举报、留言审核和管理权申诉能够完整流转。
- 手机登录自动化测试通过，但生产前台不显示入口。
- 免费版完整可用，高级权益可配置但不可购买。
- 英语、简体中文和西班牙语达到首发质量。
- 阿拉伯语 RTL 技术验证通过。
- 主页转私密或删除后立即退出站内搜索并拒绝未授权访问。
- 权限、安全、隐私、无障碍和数据恢复验收通过。

## 20. 实施前仍需在计划中细化的工程决策

以下不是产品范围疑问，不阻塞本设计确认；它们应在实施计划或相应技术任务中做出明确选择：

- 邮件、短信、对象存储、Redis 和托管 PostgreSQL 的具体供应商；
- Google 和 Apple 登录的地区开放策略；
- 首版全文搜索的 PostgreSQL 扩展与音译库；
- 宗教历法转换库及其版本锁定策略；
- 媒体文件大小、免费配额和恢复期的具体数值；
- 宗教顾问、语言审核者和平台审核员的运营工作流与服务级别；
- 各司法辖区上线前的隐私政策、未成年人保护和数据驻留评估。

## 21. 实施交接

该能力需要先编写分阶段实施计划，再进入编码。实施计划应把每个阶段拆为可独立验证的数据库迁移、领域服务、API、页面、后台任务和测试任务，并优先完成平台基础、权限、隐私和宗教配置边界。
